# Creator Match

광고주의 캠페인 조건에 맞는 크리에이터를 데이터 기반으로 추천하는 모비데이즈 P&A 사전 과제 프로토타입입니다.

공개 저장소: [upzil/mobidays-pa-creator-matcher](https://github.com/upzil/mobidays-pa-creator-matcher)

사용자가 크리에이터 1인당 예산, 관심 카테고리, 팔로워 규모를 입력하면 조건에 맞는 후보를 찾고 참여율·평균 조회수·광고주 평가·캠페인 경험·예산 효율을 바탕으로 우선순위를 제안합니다. 추천 결과에는 점수만 표시하지 않고 후보가 추천된 이유와 데이터가 부족한 지점도 함께 설명합니다.

React·TypeScript 기반 애플리케이션과 추천 엔진 구현을 완료했습니다. 별도 서버나 API 키 없이 제공 CSV만으로 실행되며, 파싱·추천·UI 흐름을 자동 테스트로 검증합니다.

## 해결하려는 문제

인플루언서 캠페인을 준비하는 광고주는 많은 후보 중에서 예산과 카테고리에 맞는 크리에이터를 빠르게 추려야 합니다. 팔로워 수만으로 판단하면 실제 도달과 반응, 협업 안정성을 놓칠 수 있습니다.

Creator Match는 다음 질문에 답합니다.

- 입력한 예산과 카테고리에 맞는 후보는 누구인가?
- 팔로워 규모가 비슷한 후보 중 성과가 더 좋은 사람은 누구인가?
- 각 후보는 어떤 데이터 때문에 추천되었는가?
- 정확히 일치하는 후보가 없을 때 어떤 대안이 가장 합리적인가?

## 핵심 기능

- 추천 전 전체 200명 목록과 팔로워·조회수·참여율·평점·협업비 기준 정렬
- 추천 실행 후 추천 후보를 상단에 배치하고 나머지 전체 목록 유지
- 크리에이터 1인당 최대 예산 입력
- 10개 카테고리 다중 선택
- 나노·마이크로·매크로 규모 선택
- 데이터 기반 추천 점수와 결정론적 순위
- 후보별 추천 근거
- 캠페인 이력이 없는 후보의 안전한 처리
- 정확한 후보가 없을 때 조건 완화 대안
- 추천 결과의 추천점수·참여율·조회수·평점·예산 기준 재정렬
- 모바일과 데스크톱 대응

## 추천 정책 요약

### 팔로워 구간

| 구간 | 기준 |
|---|---:|
| 나노 | 10,000명 미만 |
| 마이크로 | 10,000~99,999명 |
| 매크로 | 100,000명 이상 |

### 기본 가중치

| 지표 | 가중치 | 의미 |
|---|---:|---|
| 참여율 | 30% | 팔로워의 실제 반응 수준 |
| 평균 조회수 | 25% | 콘텐츠 도달 성과 |
| 광고주 평점 | 20% | 과거 협업 만족도 |
| 캠페인 경험 | 15% | 협업 수행 경험과 신뢰도 |
| 예산 효율 | 10% | 입력 예산 안에서의 비용 적합성 |

참여율과 평균 조회수는 전체 유효 데이터의 같은 팔로워 규모 안에서 평균순위 백분위로 비교합니다. 광고주 평점은 전역 평균 `4.415028901734104`와 캠페인 5건 강도의 Bayesian 보정을 적용한 뒤 동일 규모에서 백분위로 변환합니다. 캠페인 경험은 구간 최대값에 대한 `log1p` 비율을 사용합니다.

예산 효율은 알려진 평균 협업비 `C`와 입력 예산 `B`에 대해 `B / (B + C)`로 계산합니다. 비용이 미상인 후보는 중립값 `0.5`를 사용하되 반드시 견적 확인 필요 상태로 표시합니다. 전체 계산식과 실제 데이터 검산 예시는 [PRD](./PRD.md)에 기록했습니다.

평점이 비어 있는 신규 크리에이터는 0점으로 처리하지 않습니다. 중립적인 사전값과 낮은 정보 신뢰도를 적용하고 `캠페인 이력 없음`을 명시합니다. 같은 이유로 캠페인 이력이 없는 후보의 평균 예산 0원은 무료가 아니라 `비용 확인 필요`로 표시합니다.

### 후보 등급과 노출 순서

1. 정확 일치: 카테고리·규모가 일치하고 평균 협업비가 예산 이내
2. 탐색 후보: 카테고리·규모는 일치하지만 캠페인 이력이 없어 비용이 미상
3. 예산 완화: 카테고리·규모가 일치하고 평균 협업비가 예산의 120% 이내
4. 규모 완화: 카테고리가 일치하고 인접 팔로워 규모이며 예산 이내

정확 후보가 있으면 정확 후보를 먼저 보여주고 비용 미상 탐색 후보가 있으면 별도 보조 섹션에 함께 표시합니다. 정확 후보가 없으면 `예산 완화 → 규모 완화 → 탐색 후보` 중 처음으로 비어 있지 않은 단계만 표시합니다. 조건을 완화한 후보는 정확 일치 결과와 구분하고 무엇을 완화했는지 표시합니다.

마이크로 구간의 인접 규모는 나노와 매크로를 모두 포함합니다. 나노와 매크로의 인접 규모는 각각 마이크로입니다. 서로 다른 후보 등급은 하나의 순위로 섞지 않습니다.

## 실행 방법

Node.js 22 LTS 사용을 권장합니다. 지원 범위는 `20.19 이상`, `22.13 이상`, 또는 `24 이상`입니다.

```bash
npm install
npm run dev
```

개발 서버가 안내하는 로컬 주소를 브라우저에서 열면 됩니다. 별도의 환경변수 설정은 필요하지 않습니다.

전체 검증 명령은 다음과 같습니다.

```bash
npm test
npm run lint
npm run typecheck
npm run build
```

제공 CSV의 스키마와 통계는 별도 패키지 없이 다시 확인할 수 있습니다.

```bash
node scripts/profile-data.mjs
```

원본 파일은 `public/data/dummy_creators.csv`에 있으며 SHA-256은 `6f139b1a8cac4a7aa0d8034bde2df16ae7c06896ee820eec16ddafbcf2738b8c`입니다.

## 구현 구조

```text
src/
├── data/             CSV 파싱·검증·오류 행 격리
├── domain/           공통 도메인 타입과 카테고리 계약
├── recommendation/   후보 분류·점수·근거·fallback·정렬
├── components/       조건 입력과 결과 표시
└── App.tsx            로딩·입력·결과 상태 통합
```

추천 엔진은 UI와 분리된 순수 함수입니다. CSV의 일부 행이 잘못되면 유효한 행은 계속 사용하고 제외 건수를 알리며, 필수 헤더가 없거나 유효 행이 전혀 없으면 재시도 가능한 데이터 오류를 표시합니다.

## 설계 원칙

- 추천 로직은 UI와 분리된 순수 함수로 구현합니다.
- 원본 CSV를 수정하지 않고 파싱 단계에서 검증합니다.
- 모든 추천 근거는 실제 계산값에서 생성합니다.
- 누락된 데이터와 완화된 조건을 숨기지 않습니다.
- 복잡한 모델보다 면접에서 설명하고 재현할 수 있는 정책을 선택합니다.

## 주요 트레이드오프

- 실제 캠페인 성과가 아니라 더미 데이터의 과거 지표를 사용하므로 추천은 의사결정 지원 수준입니다.
- 평균 캠페인 예산을 크리에이터 1인당 예상 협업비의 대리값으로 사용합니다.
- 카테고리는 관련성을 지키기 위해 fallback에서도 유지합니다. 그 결과 후보가 적을 수 있지만 무관한 추천을 막을 수 있습니다.
- 캠페인 이력이 없는 후보는 잠재력을 배제하지 않되, 검증된 예산 적합 후보와 분리합니다.
